# 0.3.1 — 2026-11-25

## Added

- **`scheduled_service`** tri-state filter on `ourairports_search_airports`, `ourairports_find_airports`, and `ourairports_search_runways`. ([#35](https://github.com/cyanheads/ourairports-mcp-server/issues/35))
- **`dataAsOf`** on every tool result and on `airport://` output: when the bundled OurAirports data was published, read from `data/snapshot.json`, which `build:data` writes and `build:data --check` validates (`prepublishOnly` runs the check). The build accepts file `Last-Modified` values within ten minutes of each other, dates the snapshot by the latest, and refuses a wider span as two mixed deploys; a failed download names the file. Output schemas keep `additionalProperties: false`, so a client holding a cached 0.3.0 tool list must re-list tools before it accepts `dataAsOf`. ([#36](https://github.com/cyanheads/ourairports-mcp-server/issues/36))

## Changed

- **`ourairports_find_navaids`** airport mode returns each navaid's distance and bearing from the airport; they were null before. ([#37](https://github.com/cyanheads/ourairports-mcp-server/issues/37))
- Startup log key `runways` is renamed `airportsWithRunways`, and the log adds `dataAsOf` and `fetchedAt`.

## Fixed

- **`type: "closed"`** selects closed airports without `include_closed` (`include_closed_airports` on runways), even with the flag explicitly `false`, and empty-result notices name only remedies that could add rows. `search_runways`' empty notice also suggests dropping `lighted`, `type`, or `scheduled_service` and widening `radius_km` (max 20016) when those are set. ([#33](https://github.com/cyanheads/ourairports-mcp-server/issues/33))
- **Name ranking** compares tokenized forms with the `ft`→`fort`, `mt`→`mount`, `st`↔`saint`, and `ste`↔`sainte` alternatives, so "st louis" ranks Lambert–St. Louis first. ([#34](https://github.com/cyanheads/ourairports-mcp-server/issues/34))
- **One-word queries** that are a city name and another airport's code lead with that code's holders and the airports in that city; the +50 code-equality bonus now applies to IATA only. ([#38](https://github.com/cyanheads/ourairports-mcp-server/issues/38))
- Search folds ł ø ı đ ð þ æ œ ß ə ᵫ ŧ ħ to ASCII and lowercases after Unicode decomposition, so `lodz` finds Łódź. Some match sets change: `man` no longer matches Tuđman, `kobe` also matches København, and matches on fragments of unfolded letters are gone.

## Security

- Airport search matches each distinct query token and code once, so per-call matching work grows with the distinct tokens and codes in the query.
